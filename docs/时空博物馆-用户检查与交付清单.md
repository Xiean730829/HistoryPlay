# 时空博物馆：用户检查与当日交付清单

版本：1.0｜日期：2026-10-24｜关联：[AI开发任务卡](./时空博物馆-AI开发任务卡.md)、[产品手册](./时空博物馆-长廊式语音游玩开发手册.md)

## 2. 每次请用户检查前的准备

开发者提供同一张检查通知：

```text
检查：H编号、名称
版本：分支/commit/相关PR；内容包与资源清单版本
入口：实际可打开的localhost或HTTPS地址
当前设备：浏览器、分辨率、耳机/扬声器、网络条件
准备：初次麦克风授权/已登录的模拟设备；不要发送账号密码
这次只请检查：本节列出的几项
已知缺项：哪些还不能用，哪些是开发模拟
证据：截图/录屏/脱敏日志的位置
```

开发者自测通过再发起检查。检查阶段需要用户登录或麦克风授权时，在实际页面完成，不向聊天或Git提交凭据。文档安排检查不等于当前已经要求用户操作；只有版本已准备好才发具体检查请求。

每次用户回复只需“通过H2”或“需修改H2：某处不对”。开发者将原反馈摘要记入台账；收到真实反馈之前保持“待检查”。体验通过不自动授权合并或部署，PR按用户既定协作方式处理。

## 3. H0：上午确认游玩规则

**时机**：文档交付后，开始批量制作页面之前。**依赖**：CW00。**材料**：产品手册第1—6节、任务卡与本清单。

请你检查：

- [ ] 打开页面就已经在唐朝馆，主视觉是深邃长廊和文物，时间线在地面。
- [ ] 语音“往前走/往回走/看某物”移动视野；真实模型走近自动加载。
- [ ] 名称、年代、故事引子用小字；人物卡和插画只在请求故事后出现。
- [ ] 语音可转物、听稿、打断、追问、恢复、返回；无需点展品或加载按钮。
- [ ] 三物仅作联调；全馆仍沿唐朝建立、兴起、转折、衰亡组织，保留以后新朝代/海外馆的接口。
- [ ] 最终内容如实区分19个模型文件、20张卡片、照片展品、海外比较器和待核断代，不把数量硬等同为19个主展台。

**需修改判据**：任何一项与用户预期相反，先修规则再批量扩展对应页面。H0不要求用户逐条审查代码文件；技术实现可按这些已确认体验自主推进。

## 4. H1：首屏是不是你要的博物馆

**时机**：CW02b、CW05a/b可运行，先不等全部语音。**开发者先自测**：QW、三件真物预览、宽窄屏。

**用户动作**：打开给定地址，停留10秒；分别看完整宽屏和窄屏截图。此阶段允许开发者预设位置，必须标明尚未接真语音。

- [ ] 看见墙、地面、展台、聚光和向远处收束的空间，视觉主体是文物。
- [ ] 至少三个展位有清楚的近大远小与遮挡层次，文物不漂浮成网页卡片。
- [ ] 文物预览来自真实模型，背景没有白色图片框和大封面。
- [ ] 年代沿地面可辨认，当前文物名字、断代和一行钩子不抢占主体。
- [ ] 首屏没有人物海报、故事长文、包ID输入框、四列目录或大面积技术状态。
- [ ] 手机窄屏不会切掉当前文物或让小字完全读不清。

**证据**：宽屏/窄屏各一图，标记commit与分辨率；另存初始状态。**失败例**：只是黑底卡片墙；只有一张展馆插画；文物都一样大；需要先选择内容包。**反馈作用**：决定空间和陈列参数；未通过前不批量复制全馆视觉。

## 5. H2：视野是不是在长廊里移动

**时机**：CW04a/b、CW06联动；H1已确认视觉方向。**阶段标注**：工程期可用开发指令面板自测；H5/H8必须重跑真实语音，不能沿用模拟结果。

| 指令 | 你应看见 | 失败情况 |
| --- | --- | --- |
| 往前走一点 | 移动一个展位，里面的文物变大，近处展台经过视野，年代跟随 | 只有文字变化、页面上下滚动、直接切目录 |
| 往回走一点 | 回前一站，方向自然，焦点与年代同时回去 | 位置回去了但讲解对象没变 |
| 看一下铜钱 | 定位开元通宝展位，焦点是铜钱 | 搜到了却没移动，或把内容卡当模型 |
| 不看铜钱了，去看那头牛 | 移到鎏金卧牛，即使此前不在可见窗口也能找到 | 随机选择、牛加载到钱币展台、旧移动覆盖新目标 |
| 快速说前进，再说后退/换目标 | 最新有效目标收束，无回闪 | 一串旧动画过几秒依次补播 |
| 在两端继续走 | 简短说明到头，画面保持合理 | 越界、空白、掉进未开放展厅 |

- [ ] “第二件”与当时画面报告的可见顺序一致；不同屏宽不能悄悄换序。
- [ ] “近一点看看它”是放大文物，“再往前走”是换站，二者不混淆。
- [ ] 减少动态效果模式仍能辨认位置变化，不出现强制长动画。

**证据**：30—60秒连续录屏、指令来源（开发模拟/真实语音）、起止站点、实际失败点。**反馈作用**：调移动速度/深度/遮挡；顺序错误回到服务端投影修正，不用提示词掩盖。

## 6. H3：走近是否自动变成可转动的真物

**时机**：CW02d、CW07a/b/c完成，三件都有真实文件。**准备**：开发者分别准备冷缓存和热缓存，记录网络条件；不让用户在检查时手动找本机文件。

- [ ] 走到某物前就自动加载，整个过程没有“加载模型/查看3D”按钮。
- [ ] 同一展台由真预览平滑变成真实模型，物件不会突然换形、换大小或歪倒。
- [ ] 说“看背面、转一点、近一点、恢复原来角度”能看出体积和细节，转的是文物，长廊不跟着转。
- [ ] 初始朝向、亮度、材质合理；近看无丢纹理、看不见物件或巨大空白。
- [ ] 快速从A换B，A慢加载结束也不会覆盖B。
- [ ] 故意模拟模型失败：保留真实预览，说清暂未加载，仍能去下一站；不能口头说已经可转。
- [ ] 照片展品明确是照片，能放大/换照片，但不会假装旋转成立体。

**记录表**：

| 文物 | 原件/展示版MB | 冷加载秒 | 热加载秒 | 正反面/贴图 | 预览同位衔接 | 用户结果 |
| --- | --- | --- | --- | --- | --- | --- |
| 造像碑 | 待测 | 待测 | 待测 | 待查 | 待查 | 待检查 |
| 开元通宝 | 待测 | 待测 | 待测 | 待查 | 待查 | 待检查 |
| 鎏金卧牛 | 原件约33.9；展示版待测 | 待测 | 待测 | 待查 | 待查 | 待检查 |

550—900毫秒移动、缓存模型抵达后约1秒可交互、展示版约5—10MB是初始工程目标，未达标时记真实数字和体验，不伪填“通过”。超大模型必须说明优化/降级与逐件结果。

**证据**：三件正面/背面截图，一段自动加载录屏，冷热耗时及viewer数量。**反馈作用**：单件朝向/尺寸改资产framing；全体大小错改展台投影；不因此改史实或剧情。

## 7. H4：故事何时出现，能否原位回来

**时机**：CW04c、CW08a/b，接上CW12后补声音检查。**起点**：卧牛展台，先转到一个明显不同的观察角度。

| 你说 | 应发生的事情 |
| --- | --- |
| 介绍一下它 | 保持卧牛近景，读卧牛背景稿；没有擅自进入人物故事 |
| 看看它背后的故事 | 此时才展示对应人物、背景或漫画，保留简短字幕与必要创作标识 |
| 停一下，我问个问题 | 停音，画面保留当前故事镜头，不跳下一段 |
| 继续刚才的故事 | 恢复刚才被打断的片段；首版可从该片段开头重读 |
| 下一段 | 才进入下一镜头/正文，不把上一声“继续”当作跳过 |
| 回博物馆 | 收起故事图，仍在原卧牛展台，保留观察角度 |
| 再往前走 | 正常到下一展位，不从入口重新来 |

- [ ] 不把虚构人物说成原物已证实主人；图像情境与史实资料可区分。
- [ ] 文稿、字幕和当前图片讲的是同一物/同一段，不错配其他器物。
- [ ] 如果故事还没配完，只报告缺项；不拿其他人物图临时顶替正式验收。
- [ ] 退出后旧故事晚到的音频和图片不再冒出来。

**证据**：进入前物件角度、故事镜头、返回后角度三图＋连续录屏。**反馈作用**：故事表现改story；返回错误改会话锚点，不能简单让前端记个上页URL糊过去。

## 8. H5：真实小智能否用语音控制当前页面

**预检时机**：CW09p最早执行。**正式检查时机**：CW09—11接通后。预检通过不等于正式检查通过。

**准备**：开发者已配置专用小智智能体、固定模拟设备、MCP管道和当前展台绑定；你只需在本机完成必要登录与首次麦克风授权。真实入口必须显示可用状态。首次浏览器授权/音频解锁可点一次，随后主玩法靠语音。

| 你说 | 页面/声音应有的实际反应 |
| --- | --- |
| 带我看唐朝 | 进入唐朝长廊；已经在唐朝时不清空进度重建设备 |
| 往前走一点 | 声音与画面都回应，真移动一站 |
| 看铜钱，转到背面 | 定位钱币并自动加载，物件转动 |
| 不看这个了，我要看那头牛 | 找到鎏金卧牛并移动，自动出现真实模型 |
| 现在这个是什么 | 回答当前卧牛，不能仍然介绍钱币 |
| 给我讲它背后的故事 | 调用游戏进入故事，出现对应图片并听到内容 |
| 回博物馆 | 收故事层回原展位 |
| 看宋朝 | 说明尚未开放，保持当前唐朝站位和焦点 |

- [ ] 没有让用户报文物ID、工具名、配对码或输入包版本。
- [ ] 第一次配置后正常重连不反复创建设备、不每次念配对码。
- [ ] 模型没加载好时只说正在准备，不先宣称“已经可以转动”。
- [ ] 另一标签页/旧连接不能同时控制当前页面；连接失败有可见小提示，不能假装听见。
- [ ] 不需要开发者在镜头外鼠标点按钮补动作。

**证据**：全屏录屏含真实麦克风输入/实际声音/画面；脱敏工具调用记录关联到同一个会话、目标和回执。只展示MCP Online、聊天成功、字幕识别正确都不算完成。

**失败处理**：先区分采音/识别/工具调用/会话提交/事件/资源呈现哪层失败。直连不能可靠隔离时按ADR走自有控制编排；独立ASR/模型/TTS凭据缺失写明，不让用户被迫改成点击玩法。

## 9. H6：插话、追问、继续是否自然可靠

**时机**：CW09c、CW11b、CW12a/b完成；H5正式导航可用。**起点**：卧牛故事第一段正在播放，不等播放完再提问。

1. 在句子中间说：“等一下，这么小是干什么用的？”声音先停下，再回答问题；画面保留原段。
2. 再问：“普通人也会用吗？”仍围绕卧牛与当时生活，说明已知和不确定处，不切回钱币。
3. 说：“继续刚才的故事。”回到被打断的同一片段，可从片段开头重读；不能跳过该片段。
4. 说：“下一段。”这次才推进镜头。
5. 在系统准备“往前走”时立刻改口：“停下，还是看牛。”旧工具/旧音频晚到不能再把你带走。
6. 说：“回博物馆。”随后等10秒，不应突然补播已退出故事。

- [ ] 插话止声足够及时，没有一整段旧音频继续播；开发者记录speech_started到最后旧音频输出的实际延迟。
- [ ] 固定稿、自由回答、操作提示始终只有一个声音，不叠播。
- [ ] “停一下”与“下一段”不同；“继续往前”与“继续故事”不同；裸“继续”不明确时简短澄清。
- [ ] 旧任务即使重新请求context，也无法拿新授权复活旧动作。
- [ ] 同一测试连续做三轮，重连后再做一次；单次偶然成功不算稳定。

初始止声目标为本地检测发声后约300毫秒内；需记录设备/音频缓冲条件，达不到则保留问题和改进结果。云端回答耗时另外记录，不能混作止声延迟。

**证据**：可听见双向声音的连续录屏＋脱敏事件时间线（local_turn、epoch、request、playback stop/drain）；不把本地turn冒充云端turn。**阻断条件**：旧动作仍能推动游戏或双声反复出现，不能签“语音闭环完成”。

## 10. H7：全唐朝的内容是否值得逛

**时机**：CW13各卡导入后按批检查，最后全量核台账。AI先做全量引用/资源校验，你主要判断故事、画面与趣味，不要求人工逐个查JSON。

- [ ] 所有20卡都有身份/断代/来源/背景稿/故事引子/入口或明确候选状态；19模型逐件有可访问文件与展示记录，照片碗如实降级。
- [ ] 10章至少形成“建立→兴起→转折→战后重建→晚唐→907结束”的完整线索，选取每阶段入口实际走通；不是把19件器物硬排成准确制作年表。
- [ ] 文物引故事：人物生活、选择、技艺、制度、信仰、交流各有不同问题，不是每件都重复同一个宫女人生。
- [ ] 乐俑共用合奏主题，另一女俑做比较观察；后备佛像不堆成多个重复主展台。比较物、附属观察仍可从语音进入。
- [ ] 宽断代/重叠断代有诚实说明；钱币本件年代与币制开始分开，争议净水瓶不冒充确定唐代证据。
- [ ] 伊拉克碗保留地域标签；虚构人物/真实历史人物/实物主人关系分别表达。
- [ ] 未取得的冠饰、刀剑不靠AI图冒充真模型；缺项能看见清单与后续任务。
- [ ] 58个选用图ID按manifest选稿，不混被替换原图；人物设定拼版没有直接不加处理塞进故事界面。
- [ ] 图片/字幕/声音不会错绑，故事中能提问、退出，听不完也能自由参观下一件。

**固定抽查建议**：一件人物俑、一件镇墓兽、乐俑合奏、三彩瓶、铜镜、长沙碗照片、伊拉克比较器、晚唐主线。抽查不是免除其他模型自动与浏览器检查；全量结果记录每个ID。

**记录格式**：`文物/章节ID｜真实资产与来源状态｜故事入口｜图片/朗读｜用户意见｜可开放/待核/待修`。未核内容继续列出，不把“全20卡已导入”说成“20卡历史审核通过”。

## 11. H8：晚上从头参观与正式交付

**前置**：H1—H7相关结果明确；CW14a/b/c工程检查完成。尚有失败项可演示进度，但交付状态必须写“部分完成”。

你连续完成以下路线，除首次平台授权外不点玩法控件：

## 12. 证据和问题怎样记录
