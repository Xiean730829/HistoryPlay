## 5. 两线交接接口

### 复用现有游戏 HTTP

以下路由在制定时已存在；完整请求/鉴权以 main 的 routes、contracts 和 museumApi 为准，不凭本表省略字段：

| 用途 | 已有入口 | 约束 |
| --- | --- | --- |
| 当前对象 | `GET /api/sessions/{session_id}/context` | 以服务端 focus 解释“它” |
| 查找对象 | `GET /api/sessions/{session_id}/search` | 固定内容版本、稳定 ID、别名和歧义 |
| 背景/故事正文 | `GET /api/sessions/{session_id}/content` | 分段、有来源和预算，不返回整包 |
| 导航/观察/故事动作 | `POST /api/sessions/{session_id}/commands` | 统一命令、绑定、控制票据和轮次验证 |
| 浏览器呈现结果 | `POST /api/sessions/{session_id}/render-receipts` | 由真实画面报告；B 不能伪造成功 |
| 当前页面配对 | `POST /api/sessions/{session_id}/pair` | 复用现有授权链，不对外暴露凭据 |

MCP 不导入 museum.domain、SQLite，也不操纵 DOM。浏览器展示模块不导入小智协议。音频传输与 MCP 工具是不同通道：前者负责听说，后者负责查询/动作。

### B 的交接文件

`docs/integration/voice-mcp-handoff.md` 由 B 独占维护，每次有效提交后给出：

```text
代码：分支、commit、PR链接
状态：实现/本地测试/真实连接/真实工具调用分别记录
启动：可实际运行的命令、端口、进程和依赖版本
配置：只列变量名与本机配置位置，绝不列值
组件：VoiceEntry的实际导出/参数、清理方式、当前会话适配器
接口：已复用的HTTP；需要A补充的路由/字段/生命周期及测试场景
依赖集成：根依赖/锁文件/CI/边界检查的确切修改要求
证据：脱敏日志、录屏、实际失败点
下一步：A需要接入的最小补丁，及B剩余工作
```

VoiceEntry 接收当前会话的受控适配器，不能自己再次 createSession/pair 抢占页面。绑定换代时应 dispose 旧连接、清音频并使旧授权失效。props 和事件类型先在 B 模块内部定义并随交接文件给出，A 一次装配；不要先改公共 Schema 让两线同时追逐不稳定接口。

## 7. PR、合并与运行秩序

1. 一个可审查行为一个 PR；标题和普通 commit 都为 `feat(中文范围): 中文描述`。A 沿用正在进行的分支；B 新建 `codex/` 分支。默认面向最新 main，必要的前置分支必须在 PR 写明，不能把合入父分支当成入主线。
2. A 和 B 各自 worktree、测试和本地端口，不操作正在给用户看的旧预览。新服务先查占用，交接时记录实际端口；A 最终统一启动。全程不删除用户数据库或原始模型。
3. B 的新包先在本包环境验证；根工作区依赖、锁文件、CI 和边界检查由 A 一次集成。未纳入完整检查之前，该包不能记为最终工程通过。
4. B 不修改总进度台账，证据写独占 handoff；A 合并后集中登记任务/PR/H状态，避免每个 PR 都冲突同一张表。
5. 用户已授权无冲突、审查及 CI 通过后合并。指定 A 作为本次集成者：检查最新 head、审查差异、确认依赖已进 main、等待准确 head 的完整 CI 后合并，再看合并后主线 CI。B 提供 PR，不同时抢合并队列。
6. 运行 `git diff --check`、任务相关测试及当前 CI。新增语音/MCP 必须纳入静态、编译、依赖、测试及导入边界；不能用旧服务通过的 CI 证明新模块可靠。
7. 不把修改推入已有旧预览后直接宣布新版。A 切换可运行入口时记录 SHA、包版本、资源根和进程；重启前保留存档并确认当前运行任务，避免误杀另一线测试。
